## Repeat Deployment

From the repository root, use a new release identifier:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/deploy-homepage.ps1 -ReleaseId site-20261020-homepage-r2
```

The script uses an explicit public-file allowlist, validates the existing root,
checks the upload SHA256, creates a private backup, preserves existing public
verification files, and atomically changes the website symlink. It does not deploy
CRM drafts or modify Nginx. Review local changes before every release.

## Rollback

On the server, restore the verified previous target atomically:

```sh
test -d /opt/nstarbiz-site/releases/site-20260805232734
ln -s /opt/nstarbiz-site/releases/site-20260805232734 /opt/nstarbiz-site/.rollback-20261020-homepage-r1
mv -Tf /opt/nstarbiz-site/.rollback-20261020-homepage-r1 /opt/nstarbiz-site/current
```

The temporary rollback symlink must not already exist. No release directory is
deleted, and no Nginx reload is needed for the unchanged document-root path.
